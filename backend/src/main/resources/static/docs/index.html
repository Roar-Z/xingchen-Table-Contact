汇表后端接口文档

这一页是前后端联调时对照用的，字段名、参数和响应都以这里为准。接口按资源划分， 除上传外都是 JSON，字段统一用下划线命名，和前端代码里的写法保持一致。

BASE URLhttp://127.0.0.1:8000
API PREFIX/api
ENCODINGUTF-8 / JSON
BACKENDSpring Boot 3.4.5
INTENTLangChain4j 1.0.0（可选）
STORAGEdata/*.json

概览

后端只做四件事：把表格读成行、把字段对齐、按业务规则算、把结果写成 HR 能导入的文件。 所有数值计算都在 Java 里完成，大模型只在需要的时候帮忙判断“这句话是请假结算还是加班筛选”，不参与算数。

当前版本没有登录和权限体系，默认只监听本机 127.0.0.1:8000，数据落在 backend/data， 适合内网单机演示。真正部署到厂区时，建议在前面加一层网关做鉴权和访问日志。

处理流程

01上传源表 → 02解析描述 → 03确认映射 → 04试算 → 05创建任务 → 06轮询进度 → 07下载文件

第 4 步和第 5 步走的是同一套处理代码，试算只是不落文件、不写任务记录，避免出现“预览能过、正式执行报错”的情况。 任务创建后由 taskExecutor 线程池异步执行，前端每 1.3 秒拉一次详情即可。

通用约定

约定说明
命名请求和响应字段一律 snake_case，例如 file_id、output_rows。
时间任务时间精确到秒，格式 yyyy-MM-dd HH:mm:ss；预览耗时用毫秒整数。
文件支持 .xlsx、.xls、.csv，单文件 30MB 以内，一次最多 60MB。
编码CSV 优先按 UTF-8 读，出现乱码时自动退回 GBK。
源文件上传后复制到 data/uploads，处理时只读，不会改原表。
产出文件每个任务一个目录：data/outputs/{task_id}/，同名文件互不覆盖。

错误格式

所有业务异常都返回统一的 JSON，前端直接读 detail 展示即可。

{
  "detail": "工号 E11004 在年假余额表中不存在，按 0 年假处理并输出事假"
}
状态码场景
200正常返回，任务创建成功也返回 200。
400参数缺失、文件格式不支持、描述识别不出场景。
404任务编号不存在。
409文件已被清理、产出文件不存在等状态冲突。
500未预期的服务端异常，详情看后端控制台日志。

确认服务在线、当前解析模式和任务数量。

上传源表

POST /api/files/upload multipart/form-data
字段位置说明
file 必填form表格文件，支持 xlsx / xls / csv。
roleformauto（默认）、leave_request、annual_balance、overtime、target_template、unknown。

返回文件的表头、工作表信息、角色识别结果和一列样例值，前端用这些信息展示“第几行是表头”。

curl -F "file=@OA导出请假单.xlsx" -F "role=auto" \
  http://127.0.0.1:8000/api/files/upload
{
  "file_id": "Faf1b12df71",
  "name": "OA导出请假单.xlsx",
  "ext": ".xlsx",
  "size": 6803,
  "role": "leave_request",
  "role_label": "OA 请假单",
  "header_row": 1,
  "sheets": [{ "name": "Sheet1", "rows": 13, "columns": 14 }],
  "columns": ["请求标题", "工号", "申请人", "部门"],
  "sample": { "工号": "E11004" }
}
年假表的第 1 行是“2026年休假明细 2月”这样的标题，header_row 会是 2。业务代码不用自己处理，解析时按这个行号往下找即可。

字段说明
presetleave 返回 OA 请假单 + 年假余额 + HR 缺勤模板；overtime 返回 ERP 加班表 + HR 加班模板。
POST /api/demo/prepare

解析任务描述

POST /api/tasks/analyze 自然语言 → 可执行配置 
{
  "brief": "把 OA 请假单和年假余额按工号关联，先扣年假，不够的转事假",
  "files": [
    { "file_id": "F1510e5d91c", "role": "leave_request" },
    { "file_id": "F91ec597e0f", "role": "annual_balance" }
  ],
  "template_file_id": "Fbab15fe685"
}

能识别场景、关联键、部门、日期区间和字段映射建议。解析失败会返回 400，并说明没看懂哪一部分。传了 template_file_id 时，target_template.columns 直接取自该模板表头（built_in=false），不传则用内置模板。

  },

  "mapping": [
    { "target": "工号", "required": true, "file_id": "F1510e5d91c", "column": "工号", "confidence": 0.96 }

  "source_columns": [
    { "file_id": "F1510e5d91c", "name": "OA导出请假单.xlsx", "columns": ["工号", "申请人"], "sample": { "工号": "E11004" } }

配置了 HUBIAO_LLM_ENABLED=1 时，规则识别把握低于 0.8 才会问一次模型；模型只返回场景和一句提示，parser 会变成 rules+langchain4j。

POST /api/tasks/preview dry run，不写文件、不落任务 
{
  "brief": "把 OA 请假单和年假余额按工号关联，先扣年假，不够的转事假",
  "files": [
    { "file_id": "F1510e5d91c", "role": "leave_request" },
    { "file_id": "F91ec597e0f", "role": "annual_balance" }
  ],
  "config": {
    "scene": "leave",
    "template_file_id": "Fbab15fe685",
    "isolate_anomaly": true,
    "strict_format": false,
    "mapping": [
      { "target": "工号", "file_id": "F1510e5d91c", "column": "工号" },
      { "target": "缺勤类别", "file_id": "F1510e5d91c", "column": "请假类型" }
    ]
  }
}

mapping 只传用户确认过的字段即可，没传的由系统按表头词典自动匹配。column 填 null 表示这一列由系统计算（例如缺勤类别、合计小时、免打卡）。

config 字段默认说明
scene自动推断leave / overtime。
template_file_id空目标模板编号，导出列名与顺序和模板表头一致。
isolate_anomalytrue脏数据隔离。关闭后问题行照常输出，只在 warnings 里统计条数。
strict_formatfalse严格格式校验。开启后模板缺列、必填缺失直接报错终止。

创建任务

POST /api/tasks 排队并异步执行 
{
  "name": "OA 请假单转 HR 缺勤（4 月）",
  "brief": "把 OA 请假单和年假余额按工号关联，先扣年假，不够的转事假",
  "files": [ ... ],
  "config": { "scene": "leave", "template_file_id": "Fbab15fe685", "isolate_anomaly": true, "strict_format": false, "mapping": [ ... ] }
}

立即返回任务快照，status 为 queued。之后每 1.3 秒调用详情接口，进度会从 10 走到 100。

{
  "id": "T20261027-0003",
  "status": "queued",
  "progress": 5,
  "created_at": "2026-10-27 21:30:01",
  "source_files": [
    { "file_id": "F1510e5d91c", "name": "OA导出请假单.xlsx", "role": "OA 请假单", "rows": 13 }
  ],
  "artifacts": [],
  "logs": [ { "time": "21:30:01", "level": "info", "message": "任务已进入队列" } ]
}

任务状态

状态含义是否有产出文件
queued刚创建，等待线程池。否
running正在读表、计算或写文件。否
done完成，没有异常行。是
warning完成，但有异常行或提示需要复核。是
failed执行失败，或筛选后没有数据。否

任务详情

GET /api/tasks/{id} 前端每 1.3 秒轮询

返回任务完整快照，包含预览、异常日志、处理日志、配置快照和产出文件。字段说明见 TaskRecord。

任务不存在返回 404，前端会显示“没有找到这个任务”，而不是退回演示数据。

下载产出

GET /api/tasks/{id}/download/{artifact} 浏览器直接打开即可

artifact 就是任务详情里 artifacts[].name，需要 URL 编码。后端只会下载任务记录里登记过的文件，防止路径穿越。

GET /api/tasks/T20261027-0001/download/HR%E5%AF%BC%E5%85%A5_%E7%BC%BA%E5%8B%A4_20261027.xls

响应头带 Content-Disposition: attachment; filename*=UTF-8''...，中文文件名不会乱码。

FileMeta（文件）

字段说明
file_id系统生成的文件编号，后续请求都用它引用文件。
name上传时的原始文件名。
ext / size扩展名和字节数。
role / role_label业务角色代码和中文名，可在上传时指定，也可自动识别。
header_row表头所在行号，从 1 开始。
sheets / columns / sample工作表概况、表头列名、每列一个样例值。

IntentResult（解析结果）

字段说明
scene / scene_nameleave 假期余量结算，overtime 加班记录桥接。
confidence / parser把握程度和解析来源（rules / rules+langchain4j）。
join_keys / filters关联键和识别出的筛选条件，给前端展示用。
target_template输出模板对象，含列名和顺序。
mapping每个目标字段的建议来源，含把握程度。
source_columns每张源表的表头和样例值，字段映射页的下拉框用它渲染。
notes给业务人员看的提醒，比如年假表标题行、缺失工号数量。

TaskRecord（任务快照）

字段说明
id / name任务编号（TyyyyMMdd-0001）和任务名称。
status / progressqueued / running / done / warning / failed，进度 0–100。
total_rows / output_rows / anomaly_rows源表行数、输出行数、隔离异常行数。
duration_ms / created_at / finished_at耗时和起止时间。
source_files参与本次任务的源文件，含角色和行数。
artifacts产出文件，name 用于下载，path 是从 backend 目录算起的相对路径，例如 data/outputs/{id}/...。
preview / output_columns前 20 行预览和完整输出列名。
anomalies / warnings异常明细和口径提示。
logs处理日志，level 为 info / warn / err / ok。
stats / config本次统计和配置快照，用于复盘。
stats（假期场景）annual_hours 年假抵扣小时，personal_hours 事假小时，annual_rows 输出为年假的行数，annual_matched 匹配到年假余额的工号数。

Anomaly（异常行）

字段说明
row源表实际行号，方便回原表核对。
source来自哪个文件。
type年假缺失 / 时长异常 / 日期异常 / 工号缺失 / 字段缺失 / 编码异常。
reason为什么被隔离，写给人看。
raw原始行的前几列，便于快速定位。
